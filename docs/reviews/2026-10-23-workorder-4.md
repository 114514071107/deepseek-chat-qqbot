## F10：完整攒批与真实图块

新增 `batch_input.py`，main.py 的 gate/inject 共用本轮输入条目：文字、图片快照、附件引用、触发消息 id、准备状态和错误。作用域仍是前三单的 `Scope.key`，不是 uid 的最后场景。

关键行为：

- gate 在图片下载之前登记补充条目和 ready 状态。inject 等待窗口内已登记的媒体准备完成，再取一次快照。测试覆盖“文字先到、后图仍在下载时 inject 已开始”，避免只修下载完成后的理想路径。
- 原有拟人攒批等待保留。每轮额外缓冲最多八条，每条图片最多三张，合并后最多八张不同图片；超额、下载失败、转换失败、准备超时都会进入明确状态，不能假装全部看过。
- 下载复用既有公网边界；每张原始图片最多 15MiB、16M 像素，转换后最长边 1536。新接收图片留存为校验过的 PNG，并由相同字节进入最终模型请求；原 URL 不被框架再次下载。
- 动图采样最多九帧形成静态拼图，提示其只覆盖采样帧。新入站留存和回看使用该 PNG，不声称保存了原动画的所有帧或时序；旧媒体不迁移。输出表情/语音玩法沿用第三单。
- 附件在攒批中保留具体引用和名称；没有读取正文时明确标记“仅留存，未读取正文”，不以控制台留存冒充模型已读取。
- `BudgetProvider` 同时核对最终框架 messages 和 OpenAI 实际 `_query/_query_stream` 载荷的图片数量、提供商能力。图片被准备/转换/能力过滤移除时拒绝模型调用并给出原因，不在兼容重试中静默删图。
- 实际框架集成使用真实 Image、ProviderRequest、图片准备、runner.reset、OpenAI 请求组装；网络停在替身 `_query`。检查的是 data URL 图片内容块及 PNG 字节，不只看 image 配置或文件存在。

## F11：有限资源、实际调用与阶段测量

新增 `resource_budget.py` 和 `model_integration.py`。接口：

| 接口 | 语义 |
| --- | --- |
| `Resources.run(lane, factory, budget, stage, timeout)` | 有限工作槽、有限等待队列、阶段及请求截止；同任务嵌套不会自锁 |
| `Resources.thread(fn, ..., _lane, _budget)` | 有限同步 I/O/媒体工作；取消 await 后，真实线程结束之前不归还槽 |
| `Resources.budget(identity, guard, parent)` | 请求/后台工作身份对应的计次、工具步数、输入和截止；活跃预算不能被缓存逐出而刷新额度 |
| `BudgetProvider.text_chat / text_chat_stream` | 模型真正进入提供商之前计次、限制重试/输出/文本输入，并验证图片 |
| `BudgetContext` | 在框架 build_main_agent 阶段保留 Provider 类型检查，同时约束请求钩子之前的图片描述调用 |
| `QQDelivery(..., media_run, media_thread)` | 媒体转换、上传和读取进入对应有限池；实际消息 POST 仍保留 F06 的一次发送与 unknown 语义 |

前台模型/工具、后台模型、前台媒体准备、后台媒体有独立容量。Runtime.spawn 标记后台工作，后台图库/摘要不会占满前台准备槽；纯文字消息解析不竞争媒体槽。后台任务总数有限，重复工作仍按第二单去重。

普通用户实际工具入口同时消耗原权限额度和新增工具预算，工具结果超过上限会标明截断。安全拒绝、主人边界和工具代理身份检查保持原样。

AstrBot 4.29.1 OpenAI 的 SDK 重试原本已关闭，但兼容循环仍可能换 key、删图片或重组请求。本轮使用请求级提供商副本，禁用该隐藏恢复循环，每次物理查询只允许一次 HTTP 尝试；框架的有限回退/空输出续试共享本轮调用计数。没有新增插件层网络重试。其他提供商或框架升级必须重新核验内部调用方式，不能直接外推本轮 OpenAI 证据。

发现该版本 `_prepare_chat_payload` 丢弃 `max_tokens` kwargs 后，已在物理 `_query` 和 `_query_stream` 载荷再次注入输出上限；保留调用方更小的值。返回正文、推理文本和工具参数另受字符兜底约束，单个超大流式 chunk 也会被拒。QQ 正常回复继续按 F07 非流式计划发送。

每个前台触发有处理截止。延后复活阶段在有意等待结束后开始自身技术截止，但与原触发共享调用/工具计数，不能靠延迟刷新额度。真正定时后台每次工作有新预算；长期循环复用同一个 asyncio.Task 不会导致第二次工作继承上次过期预算。所有工作仍受原 Runtime 版本、请求、开关和删除撤销约束。

persona、图库目录、上下文构建和私聊归档检索进入有限工作线程。归档检索默认只读最新 32MiB、最多返回当前来源的 4000 条；当前群也限制检索条数，超限明确提示范围和可能遗漏。损坏/不可读不会伪称无历史，读取不追随不断追加的新尾部。原始归档不删除。状态和历史写入仍在原单一所有者路径串行完成；没有将共享状态整表写入简单丢到线程中，也不声称所有磁盘阻塞已经消除。

阶段记录分 `queue`、`batch`、`model`、`tool`、`media`、`send`、`intentional_wait`。Resources 保留最近 512 条无正文计时元数据，主请求结束时写入现有事件 trace 的 `dsh_request_stages`；记录关联请求 id、耗时和状态，不复制聊天、媒体字节、密钥或上游原始错误。后台后续阶段仍可在有界运行时计时中诊断，不把技术等待和拟人节奏混算成模型耗时。

既有 usage 辅助场景字符统计现在包含实际传入的 contexts；主对话仍记录 API 返回的 token，两种单位不相加冒充账单。失败尝试由资源预算计数，不能从旧成功调用计量推导全部费用。

## F12：唯一历史来源与可核验压缩

新增 `context_window.py`。`build_window(rows, current_ids, scope, limit, previous)` 产生角色消息和带 `version/scope/source_version/retained_ids` 的原文摘录；`fingerprint(rows)` 用于保存前的来源快照校验。

- 插件来源历史是主对话唯一输入历史；当前批次 user 已在当前 prompt，不再出现在 contexts。较早 user/accepted assistant 进入各自角色消息，不再拼进当前 user prompt。框架持久化仍由第三单投影实际对话，不保存注入背景。
- 主提示明确当前群或私聊、当前发言者、历史来源。私聊笔记只在私聊使用；不新增公开画像字段，群不注入私聊长期记忆。
- 默认主窗口 10000 字符预算，近期最多十二条，较早部分优先摘录含目标、确认、待办、约定、更正等线索的原句。摘录保留说话者、消息标识、时间；互相矛盾的说法不会被合成一个“事实”。这是确定性原文压缩，不是模型生成的新事实。
- 超出窗口会标明省略/截断，不能承诺保留无限长对话的所有细节；需要核验时用带来源、带检索范围的 recall。关键词命中本身不等于事实成立。
- 原文摘录可在滚动窗口推进时延续，但须有可信保留条目 id 的连续性；清空滚动历史后不能靠保留摘要恢复已清内容。摘要层删除继续覆盖 session 文件。保存前检查 Runtime 和历史指纹，新消息或删除之后的旧结果不能回写。
- 旧的无版本 summary/mood 仍留在原 session 文件，不猜测重写，不自动注入。旧无 accepted 的 assistant 和无可信来源的条目不进入新模型历史；本地旧档仍保留。
- 念头、主动消息、复活等后台生成实际传入该作用域的近期角色历史；后台场景不再固定写“私聊”。记忆提炼和 react 也只使用来源/接受状态明确的对话。
- `_refresh_summary` 改用本地摘录，不额外调用模型。压缩不会删除滚动、归档、媒体或私聊笔记。
