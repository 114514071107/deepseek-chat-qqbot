# 用户与记忆入口修复记录

2026-10-28，基线 dev / 22c8d4f。用户确认：允许本人首次补充称呼或验证关联，之后 Bot 自动归类。此次按该选择实施，不修改真实身份映射、配置或旧聊天文件。当前补充构建 `20261028-identity-2`；首次 identity-1 的部署事实保留在发布记录。

## 核实的问题

1. 记忆页调用 `/api/switches`，按原始 uid 列人；用户页已使用 `/api/people`。同一个人被拆成私聊、多个群及历史文件，两个页面的目录不一致。
2. 单一可信会话来源仍被标为 pending，维护者须手动确认每个新用户。可信来源应直接建档；跨场景关联才需要同人证据。
3. QQ 官方群成员标识和私聊用户标识有不同作用域；同昵称、相同字符串或第三方昵称查询不能成为普遍同人证明。缺少平台资料时需要本人补充称呼和验证。
4. 旧记忆页按会话 uid 读取长期记忆，群聊实际长期记忆键为个人记忆键，可能显示空白；未验证跨域相同 sender 的共享键也不能直接归到某个人物。

部署前只读目录盘点为 7 个已人工确认入口、9 个会话来源、4 个已关联旧档、5 个无聊天资料键、18 个原始键。保留这些已有人为决定，不据截图猜测真实人数，不重新迁移或合并实际数据。18 个键也不能作为人数计数。

## GitHub 研究及接口限制

围绕腾讯文档/SDK、AstrBot、LangBot、NoneBot QQ 适配、Koishi 官方 QQ 适配及相关实现/issue 做了多轮检索；只以具体代码和官方说明支持能力结论。

- [腾讯标识域说明](https://github.com/tencent-connect/bot-docs/blob/645787a45937e5d9c4f0f61afefdffde0f38696e/docs/develop/api-v2/dev-prepare/unique-id.md)：不同应用的用户标识不同；群成员 OpenID 存在群作用域。不能从任意群成员 ID 直接推导私聊用户或真实 QQ 号。
- [腾讯 botpy 消息结构](https://github.com/tencent-connect/botpy/blob/e25f3e84bad7217357d8200a9d12939b58285b84/botpy/message.py)：标准群聊/C2C 作者结构分别以 member_openid/user_openid 为核心，不能保证每条消息都提供全局 QQ 昵称。本项目已能从匹配原始事件观察到的 username 读取平台称呼；有则使用，不能把缺失资料编成真实 QQ 昵称或 QQ 号。
- [LangBot 官方 QQ 适配](https://github.com/langbot-app/LangBot/blob/6b57a1074ff4002a0153f667435c2418b617f0f3/src/langbot/pkg/platform/adapters/qqofficial/api_impl.py)的用户资料接口使用本地缓存；缓存缺失时并非通用官方查号渠道。
- [qq-crack 实现](https://github.com/koishi-shangxue-plugins/koishi-plugin-adapter-qq-crack/blob/78c6b55df2825593a86be76413e7758607f4cc8c/src/bot/index.ts)默认把 appid/openid 发到第三方昵称查询 API。此次不采用、不调用，不向外部传递真实用户标识。

结论：官方资料存在时自动读取；未取得资料时由本人一次设置“称呼”，清楚标为 self_selected。群私聊的不同身份域通过本人验证关联，后续同来源自动匹配。新群产生新身份域时仍需一次验证，不能承诺未授权的全局查号或无限跨群自动识别。

## 实施

- 新增本地 `user_directory.py`：1–32 字符的本人称呼、私聊取码→群聊认领→原私聊最终确认。80 位随机码、5 分钟期限、只存哈希、重复认领/过期/重放/跨应用拒绝；不同人竞争认领时取消该次验证，私聊发起者才能确认。每人 10 分钟最多发起 5 次、待验证总量 128、每人物最多 20 来源、文件 2 MiB/来源 10000 上限，互斥和原子写入。
- 自助命令经过可信原始事件、平台/实例/机器人/应用及当前场景核验；尊重启用/回复开关，停在本地入口，不调用模型、不扣聊天积分，不把配对码写入插件聊天档案。平台/框架自身的消息留存不由此声明删除。普通无昵称来源在普通文字回复中附一次补充称呼提示。
- 新可信来源自动建档。Console 读取本人证明，仍保留人工关联、解除/否认及平台证据冲突，不因同名合并。单来源建档不等于证明任意其他来源属于同一人。
- 用户页默认全部消息；记忆页使用相同人物目录与全部/私聊/群聊/旧档筛选。每条消息保留具体场景、发言者、原始来源。本人称呼优先；平台名、群名片、历史称呼保留各自性质。
- 长期记忆按实际个人记忆键读取，同键只显示一次；多人未验证共用键暂不归属。未带场景的 Markdown 记忆明确标注场景未逐条记录。混合旧档的无来源摘要/念头不猜测归属，未拆分旧档仍只读可看；聚合入口不会变成操作 uid。念头删除按钮绑定渲染时的具体原来源，不读取全局 curUid。
- 仅管理展示合并，不改变模型上下文、群共享历史、长期记忆写入、认证/权限、积分或发送目标。旧记录和文件不迁移、不删除；原 R01、F09/TTS 等政策不变。
