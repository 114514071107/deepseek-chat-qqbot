## 失败证据与计划

- 原顺序探针本轮重跑 **3 项，2 通过/1 失败，0.554 秒，退出 1**。长消息三改二实际 `(额度、入队、计划、发送)=(3,3,3,3)`，预期全为 2。输出 `local/count-order-fix-2026-10-25-red.txt`，原断言不修改。
- 根因：额度读取顺序为“完整当前正文 → 当前正文的截断前缀 → 补充”，最后一个总数规则因错误来源顺序读回旧三张。
- 修复：在第一次 inject 固定来源有序的数量输入，完整当前正文一次 + 真正后续消息；数量预算只读该快照，未经过 inject 的直调保留当前正文兜底。消息副本按身份排除，文本相同但身份不同仍作为真正补充；完整补充文本仅供请求内数量约束，不扩大模型输入或持久化历史范围。
- 将原三项纳入常规回归，补主消息重复身份/真实同文补充、补充长消息尾部更正、重复 inject、事件后续改写与代码/引用保护。先失败再修复，继续验证额度/入队/计划/实际发送和保存结果。
