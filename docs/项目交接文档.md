## 一、项目概述与缘由

### 1.1 ds娘是什么

ds娘（DeepSeek 娘）是一个有人设的 AI 聊天伙伴：毒舌、损人专挑痛处、会阴阳怪气，"只会嫌弃，从不嘴软"，粗口是日常标点（仅限主人上下文），本质是一个有长期记忆、会主动找主人说话、会发表情包和语音的猫娘式角色。人设定稿于 NapCat 时期（见 `2026-08-23_dsh_wsl2_migration.md` 增补 H/I/J/K），人格文档为精简重构版 `persona.md`（44 行）。

### 1.2 演进史

| 阶段 | 时间 | 形态 |
|---|---|---|
| 网页端 | 2026-08-17 起 | DeepSeek 网页装饰版（dsh-web-decoration），人设/记忆/动作协议诞生于此时（brain.js） |
| NapCat 上 QQ | 2026-08-22 | QQ 小号 + NapCatQQ（OneBot v11 正向 WebSocket）桥接，主人私聊（`2026-08-22_deepseek_mascot_qq.md`） |
| WSL2 迁移 | 2026-08-23 | 桥接迁至 WSL2（`2026-08-23_dsh_wsl2_migration.md`） |
| 功能爆发期 | 2026-08-28 ~ 08-31 | TTS 语音、识图、表情包系统、智能回复三期、多用户隔离、Function Calling 工具化、旧控制台 |
| **AstrBot 移植** | **2026-09-01** | **弃用 NapCat，迁到 AstrBot + QQ 官方 Bot 接口（qqofficial）** |
| 无缝衔接修复 | 2026-09-01 ~ 09-03 | 69 节修复记录（见 seamfix 备忘录），本阶段是本项目最复杂的部分 |

### 1.3 为什么移植到 AstrBot

NapCat 是第三方协议端，逆向 QQ 协议，**有封号风险**。QQ 官方 Bot 平台（q.qq.com）提供官方 WebSocket 接口，账号风险低。AstrBot 是开源聊天机器人框架，自带 qqofficial 平台适配器、模型供应商管理、工具调用循环和插件体系。移植 = 把 NapCat 时期积累的人设、记忆、风格、全套功能在 AstrBot 上以**单文件自研插件 `astrbot_plugin_dsh_soul`** 重新实现，并逐条对齐行为（"无缝衔接"）。

### 1.4 当前形态一句话

QQ 官方 Bot（appid 在 q.qq.com 注册获得）收发消息 → AstrBot 4.x 框架 → dsh_soul 插件注入人设/记忆/风格并接管回复后处理 → DeepSeek API（deepseek-v4-flash）生成 → 碎片式多气泡滴灌发出；另有一个 Node.js 控制台（端口 7850）做管理；语音由本地 GPT-SoVITS（WSL2，端口 18765）合成。

## 二、系统架构

```
主人/好友 (QQ App)
   │  私聊消息（QQ 官方 Bot 协议，WebSocket）
   ▼
QQ 官方 Bot 平台  ──凭据: appid + secret（存于 AstrBot cmd_config.json）
   │
   ▼
AstrBot (D:\dsbot, venv, 进程 astrbot.exe)
   │  platform: qqbot-YOURBOT (qq_official)
   │  provider: deepseek (deepseek-v4-flash)
   │            vision_ds (deepseek-v4-flash-vision-exp，识图)
   │            gsv_ds   (gsv_tts_selfhost → http://127.0.0.1:18765)
   │            edge_tts_ds（备用 TTS）
   │
   ├── 插件 astrbot_plugin_dsh_soul (main.py, ~3550 行单文件)
   │     on_llm_request(inject)  → 组装 system_prompt（人设+记忆+工具指南+历史+时间行）
   │     on_llm_response(capture) → 记录历史/usage 遥测/表情包与动作标记剥离
   │     回复后处理 → 气泡切分(≤2条) → 滴灌发送（可打断）
   │     28 个 LLM 工具（recall/表情包/文件/闹钟/下载/压缩/shell/Kimi外包/搜索…）
   │     后台循环：desire(主动想话题)/proactive(主动发消息)/alarm(闹钟)/reminder(三餐提醒)
   │     数据落盘：D:\dsbot\dsh_data\（history_all.json、归档 jsonl、积分、图库…）
   │
   ├── GPT-SoVITS TTS 服务（WSL2 Ubuntu，0.0.0.0:18765，systemd 用户服务）
   │     自训练音色（v2Pro 底模 + 参考音频），输出 SILK 语音
   │
   └── dsh-console 控制台（Node.js，http://127.0.0.1:7850）
         server.js + public/index.html
         用户管理/聊天记录(图片可看语音可听)/功能开关/积分/管理员代发/
         进程开关(启动/停止/重启 astrbot.exe)/今日模型调用+缓存命中率
```

**数据归属原则**：AstrBot 框架自己的会话库（`data\data_v4.db`）只管框架上下文；**ds娘的记忆与历史全部由插件自管**（`D:\dsbot\dsh_data\`），框架配置只管模型/平台/提供商。改人设去 `dsh_data\persona.md`，不要动 AstrBot WebUI 的 persona（其为空，备忘录 §38 已查证）。

## 四、功能清单（逐项标注出处）

### 4.1 聊天主链与风格

1. **碎片式多气泡回复**：回复切成多条气泡发出，每条一句话 10 字上下、宁短勿长，允许半句/语气词（NapCat【分寸】+碎片化指令移植；验收清单一/二）。**气泡硬上限 2 条**（备忘录 §33→§50，对齐人设"一般一两句"，防刷屏）。
2. **气泡滴灌可打断**：第一条气泡发出后对方来了新消息，剩余气泡作废不再发，下轮一次性告知她"没发出去的部分"（备忘录 §26）。
3. **智能攒批**：连发消息等待合并——"对方还在输入才等，否则立即响应"启发式：距上条 ≤8s 视为连发等窗口；消息 ≥8 字或带句末标点视为"说完了"立即响应；冷启动完整句也做 2.5s 短防抖抓补刀（备忘录 §37、§50；常量 BATCH_WAIT=3.5/BATCH_QUICK_WAIT=2.5/BATCH_STREAK_GAP=8.0/BATCH_DONE_MINLEN=8）；静息档：距她上次开口 ≥10 分钟则随机等 5~10s 再回（§57）。
4. **连发编号汇总**：多条气泡连发时她能汇总回复（备忘录 §36）。
5. **react 抢答（情境化即时反应）**：感知到她"正在输入"——收到消息 20% 概率（§52）先甩一句即时反应（"让我看看""等下"），由 LLM 带全人设+最近 4 轮上下文按对方话语情境生成（§56 质量改造），固定语料兜底（备忘录 §15、§32）。解决"她思考时我再发消息她接不住"的体感。
6. **开场白固定回复检测**：醒醒/在吗/闭嘴/睡觉去等指令词正则（WAKE_RE/QUIET_RE/SLEEP_DUR_RE/SLEEP_UNTIL_RE）——休眠/闭嘴整套命令（备忘录 §2 高危项修复）。
7. **合并转发算法**：NapCat 气泡合并输出规则移植（备忘录 §10）。
8. **上线问候**：距上次 >12h 才发，持久化（`_startup_greet`）。
9. **主动消息**：desire 循环（10 分钟一想话题，5 分钟→已降频 600s）+ proactive（主人：15min 空闲/40min 间隔/每天 15 条/8~23 点（§54）；好友 24h/1 条/9~22 不变，备忘录 §2）。
10. **三餐/睡觉提醒**：午 11:30-13:00、晚 17:30-19:00、睡 23:00-01:00，每窗每天一次（`_check_reminders`；"提醒 开/关"命令）。
11. **sprinkle 旧话重提 / revive 冷场复活**：延时补话与冷场重开（`_sprinkle_later`/`_revive_later`；好友跳过"旧事新想"，备忘录 §2）。

### 4.2 多模态

12. **表情包系统**：3 个图库（official-001/dafeiyu-001/collect-001），按情绪桶（MOOD_WORDS：happy/angry/sad/shy/confused/daily/baka/like/sleep…）+ 关键词别名（EMOTION_ALIAS）检索；回复中「动作：表情 X」标记桥接发图（备忘录 §9）；表情包目录 20 行注入 system_prompt 防乱配（§35）。
13. **自主图库**：聊天中收到的新图自动存入 collect-001 私藏图库，vision 模型自动打标签；她有三个管理工具（list/retag/delete_sticker）自主管理图库（备忘录 §27）。
14. **语音 TTS**：「动作：语音」末行触发，GPT-SoVITS 自训练音色合成 SILK 发出，文字不重复发（备忘录 §2 高危项）；语音文件定期清理（`_prune_voice_dir`）。频率目标：每聊 4~5 句来一句（主人 09-01 13:30 定）。
15. **识图**：vision_ds（deepseek-v4-flash-vision-exp）；修复过 modalities 空列表 400 的根因（备忘录 §12）；image_caption 走框架 ltm。
16. **图片自动收集（harvest）**：收到图片消息时自动存图入库（消息钩子，非她主动调用的工具），并由识图模型自动打标签；收图链路 9-03 已修复并端到端验收通过（本地路径收图 + 尺寸 1KB~4MB，§68/§69）。
17. **文件收发**：她能发文件给主人（send_local_file：txt/word 等）、收主人的文件并改完发回（read/write_local_file、read_word/write_word 支持 docx）（备忘录 §25）。
18. **聊天媒体留存**：收到的图片/语音落盘 `media\`，控制台记录页直接看图、直接听语音（备忘录 §22；`/api/media`）。

### 4.3 记忆与查询

19. **滚动历史 + 全量归档**：history_all.json 滚动窗 + history_archive.jsonl 全量；recall/peek 可查全部记录含 NapCat 前世，不再受 150 条窗限制（备忘录 §29）。
20. **长期记忆笔记**：record_note/delete_note/learn_meme（梗图鉴）/record_thought；每 12 轮 extract 提炼笔记（原 8 轮，降本改 12，备忘录 §34）、每 16 轮 session 摘要（原 8）。
21. **recall(query)**：查证纪律注入——"你的聊天记录、记忆和梗图鉴都能用 recall 查到"（CHATTER_DISCIPLINE）。
22. **会话滚动摘要**：[进展]/[状态] 段（备忘录 §2 修复项）。

### 4.4 多用户与权限

23. **多用户隔离**：按 openid 分文件/分键；主人 openid `<主人openid>`（代码常量 MASTER_OPENID）。
24. **主人 vs 好友差异**：爆粗口许可仅主人上下文注入（备忘录 §2）；安全闸 `_flash_unsafe` 好友全量两道、主人豁免（§34 复核）；好友侧提示词"主人→对方"机械替换，不出现"主人"一词；非主人功能与主人对齐（备忘录 §14 好友对齐与安全审计 + SSRF 修复）。
25. **积分限额**：用户发一条扣 1 积分；控制台可分配积分、配置每日赠送（备忘录 §21；`points_all.json`；`/api/points*`）。
26. **功能开关**：全局 9 键（+kimi 外包总闸，§67）AND 每用户 10 键（reply/voice/proactive/desire/sprinkle/revive/harvest/reminders + alarm/files 好友 skill 闸门，§58）同时开才生效（备忘录 §19；主人 09-01 16:38 问的"同时开才生效"即此设计）。
27. **备注名制**：用户以备注名+QQ 号显示，不用裸 openid（备忘录 §20）。

### 4.5 主人 agent 能力（自然语言触发，非硬指令）

28. **查记录/查数据**：`peek_user_data`——主人说"看看 XX 跟你的聊天记录"她自己调工具查，且她知道这是其他用户的相关内容；用户查不到别人的（备忘录 §20/§21 工具化替换原「记录」命令）。
29. **本地文件三件套**：list_files/read_local_file/search_in_files——找文件、读文件、搜内容（备忘录 §24）。白名单根：`D:\dsbot`、`C:\Users\<用户名>\Desktop\AI专属工作文件`（LOCAL_READ_ROOTS）。

## 五、关键实现要点

### 5.1 消息流水线（收到 → 发出）

```
消息到达 gate()
  → 安全硬关键词预筛(好友) / 积分扣减 / 开关检查 / 休眠指令拦截
  → 攒批判断（连发等窗口 or 立即响应；20% react 抢答先发出）
  → 框架 LLM 循环：
       inject(on_llm_request): 组装 system_prompt（§34 顺序）+ 好友剔除主人工具
       DeepSeek 生成（可触发 28 工具：recall/表情/文件/闹钟/下载/压缩/shell/Kimi外包/搜索…）
       capture(on_llm_response): usage 遥测 → 动作标记剥离 → 历史+归档写入
  → 回复后处理：气泡切分（≤2）→ 滴灌发送（_drip_send，间隔 1.8~3.2s 随机）
       滴灌中来了新消息 → 剩余气泡作废，下轮告知（§26）
  → post_send：表情包跟随发送 / sprinkle / revive 挂延时任务
```

### 5.2 提示词结构（定稿，两处来源对照）

- 拼装顺序（缓存友好版，§34）：persona → CHATTER_DISCIPLINE → TOOL_GUIDE+表情目录 20 行 → PLATFORM_LINE → 主人权限行 → notes → memes(15) → session 摘要/mood → 最近表情包 → hist(30) → thought → 时间行（尾）。
- PLATFORM_LINE 语义：你在 QQ 私聊（官方 Bot，不是网页）；回复短毒两句以内；动作清单；括号动作禁令；语音必须末行「动作：语音」。
- 人设风格锚点（验收清单一）：三句示范台词锚语感；禁止粗口降级为"服了/无语"；旁白化协议（「旁白：」前缀的事件才算事实，「主人说：」才是主人说的）。
- 模型参数：deepseek-v4-flash，temperature=1（§16：缺失曾导致重复回复）；主链思考档 high + maxTokens 1500（NapCat 规格，AstrBot 侧经 cmd_config 承载）；**不用 Pro**（reasoning_content 吃 max_tokens 导致 function calling 空回）。

### 5.3 工具清单（28 个，main.py 内注册）

recall、peek_user_data（主人）、read/list/write_local_file、search_in_files、send_local_file、download_file（主人）、zip_files/unzip_file、run_command（主人 shell）、ask_kimi（主人，Kimi Code 外包）、set/list/cancel_alarm、read_word/write_word、learn_meme、record_thought、record_note、delete_note、get_current_time、web_search、fetch_url、send_sticker、list_stickers、retag_sticker、delete_sticker。好友请求按组剔除：MASTER_HARD_TOOLS 7 个永不开放（peek_user_data/search_in_files/read_word/write_word/download_file/run_command/ask_kimi），闹钟三件套与文件六件套分别受按用户开关 alarm/files 控制（§58）。

### 5.4 成本结构（一张图）

```
每请求输入 ≈9700 tok
├─ 工具 schema ≈5820 tok（好友剔除 12 个后减半）  ← 稳定，可缓存
├─ 稳定系统段 ≈4.4k 字（人设/纪律/指南/平台行）   ← 稳定，可缓存
```

### 6.3 Git Bash on Windows 的坑（反复踩过）

- Git Bash 里调 cmd 必须 `cmd //d //c`（双斜杠，否则 MSYS 把 /c 转成路径）。
- curl 不要直接在命令行写中文 JSON（GBK 乱码）——写临时文件 `-d @file` 或纯 ASCII payload。
- 批处理文件（.cmd/.bat）内容必须纯 ASCII（中文会乱码导致执行异常）。
- tasklist 等输出是 GBK，管道后接 `iconv -f gbk`。
- 嵌套 cmd 展开 %PATH% 会被特殊字符截断——启动必须走脚本文件（§3）。
- cmd 每次启动报 'oaming' 错：注册表 `HKCU\Software\Microsoft\Command Processor` AutoRun 的 conda_hook.bat 残留，无害（§3）。

- 闹钟存 uid 归属（老数据视为主人的），好友只能看/删自己的，每人最多 5 个启用中，到点按归属分发。
- MASTER_HARD_TOOLS 7 个永不开放：peek_user_data（他人隐私）、search_in_files/read_word/write_word（任意路径）、download_file（联网下载写盘）、run_command/ask_kimi。
- 生效链路：inject 按组剔除好友 ToolSet（schema 不占好友输入）+ 工具函数内 uid 闸双保险；好友提示词有【你能为对方做的事】指南段（开关关着不出现）。
- USER_PERM_KEYS 8→10 键；控制台 USER_KEYS 同步（API_VER 20260902-2）。

### 11.3 收图链路修复（§68/§69，已端到端验收）

- 根因：QQ 官方适配器在消息到达插件前已把来图落成本地临时文件，Image 组件的 url/file 是**本地路径**而非 http(s)，旧收图代码只认 http(s) → 一律静默跳过，收图链路自 9-01 建成后从未成功过一次。次因：尺寸下限 8KB 过高，QQ 会把小表情压到几 KB。
- 修复：本地路径存在即直接读字节；收图尺寸窗口改 **1KB~4MB**；所有静默出口（尺寸/重复/非法路径）写诊断日志。
- 9-03 12:59 实测：发 7548B 小表情 → 收图 → vision 打标 → 归位 collect-001 → index.db 落行，全链路通过；来图留存（media/inbox）同步生效。
- 顺带修复：下载工具指定 save_path 时不建父目录导致连续失败的 bug（§68）。

### 11.4 回复节奏与抢答调参（§50~§57）

- **BUBBLE_CAP 3→2**（§50）；冷启动完整句不再零等待秒回，改 2.5s 短防抖抓补刀（§50）。
- **静息档**（§57）：距她上次开口 ≥10 分钟视为静息，回复前随机等 5~10s（上限 15s），全用户生效，拟人"放下手机又拿起"。
- **抢答**（§52/§56）：概率 30%→20%；生成重写为全人设 + 最近 4 轮上下文（此前"裸奔"导致质量低），上限 12 字，timeout 5s / max_tokens 60，固定语料仅兜底。
- **思考中插话重想**（§53）：生成中途来新消息 → 整轮压住（不发气泡、不记历史），下轮告知她"没能说出口的部分"；被压轮 token 照付换干净体验。
- **主动开场**（§54）：主人侧 空闲 15min / 间隔 40min / 每日 15 条 / 时段 8~23；好友侧不变（24h / 1 条 / 9~22）。
- **埋头反馈**（§59）：连续工具调用第 3 个续轮时插一句固定语料反馈（"在弄了在弄了"类），零 LLM 成本。
- 框架侧（§51，`cmd_config.json`，非插件代码）：`max_context_length` -1→8、`context_limit_reached_strategy` 改 `truncate_by_turns`，单轮输入从 ~104k 降至 ~16k——新部署建议照此设置。
